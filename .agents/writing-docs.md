# Documentation for this fork

Update the human-facing page in `docs/<bucket>/<skill>.md` when a promoted skill changes behaviour. Describe the maintained fork's actual behaviour; upstream pages may describe an older workflow.

Keep the page concise. Include `What it does`, `When to reach for it`, `Common questions`, `It's working if`, and `Where it fits`. Add prerequisites only when the workflow requires them. State invocation mode and the boundary with similar skills. Observable outcomes are more useful than reproducing the skill's steps.

Use questions supplied in the current task or already documented for the skill. A behaviour-sync edit does not require an audience-research project, an upstream issue search, or loading historical changelogs. Do not invent reports of user behaviour.

Use absolute links to this fork's maintained docs or source, under `https://github.com/bandoyer/skills/blob/main/`. Preserve upstream attribution and existing historical source links where relevant. Do not imply edits to this fork update aihero.dev.

Keep the top-level and bucket README entries and `ask-matt` routing consistent with changes. Installation instructions remain in `install-block.md`; skill docs do not duplicate them. Follow the repository's no-em-dash prose convention.
